Unidad 4. HTTP, REST y diseño de contratos de API

Las APIs REST son el punto de unión entre frontend, backend y terceros, por lo que un contrato claro evita ambigüedades y retrabajos. Dominar métodos HTTP, códigos de estado, modelado de recursos, idempotencia y paginación permite diseñar servicios predecibles y fáciles de consumir. Esta unidad practica decisiones de diseño y corrección de errores comunes en endpoints reales.

Ejercicio 12. Elegir avanzado: decisiones y trade-offs

  1. Requisito ambiguo: (definir contrato y validar / asumir / implementar sin acordar).
  2. Fallo transitorio de dependencia: (retry con backoff y límite / reintento infinito / ignorar error).
  3. Cambio incompatible: (versionar/migrar / romper silenciosamente / no avisar).
  4. Acceso a datos sensibles: (mínimo privilegio y controles / acceso amplio / exponer en logs).
  5. Degradación de rendimiento: (medir y optimizar cuello / optimizar a ciegas / ignorar).
  6. Entregas frecuentes: (CI con gates / deploy manual sin pruebas / saltar revisión).

Ejercicio 13. Transformar avanzado: de frágil a robusto

Transforma a una alternativa más segura y mantenible.

  1. Implementación sin validación → añade validación/guards explícitos.
  2. Valor/config hardcodeado → uso de configuración por entorno.
  3. Flujo sin manejo de errores → manejo consistente y respuesta adecuada.
  4. Operación sin trazabilidad → logging/métricas con contexto.
  5. Componente acoplado → separación de responsabilidades (indica extracción).
